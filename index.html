Local inference hardware / Prices checked 1 Nov 2026

Every rig is short of bandwidth or short of room.

Token generation is memory-bandwidth-bound, and the size of the model sets the minimum memory you need. Those two numbers determine almost everything else, and nothing here offers plenty of both at a reasonable price. What you are really buying is memory. At current prices, every M5 Ultra configuration costs about $52 per gigabyte of usable memory, versus $70 for a DGX Spark and $188 for an RTX 5090. This page compares eleven ways to run models locally on memory, speed, long-context behavior, software and price, and ends with a recommendation for each priority.

Software support, and the catch

The R9700 is better supported than AMD's integrated chips. AMD's software problems are worst on Strix Halo (gfx1151), where Vulkan beats AMD's own ROCm by 2.5× and PyTorch needs community wheels. The discrete R9700 is gfx1201, and AMD lists it as officially supported by ROCm 7.2 on Linux and Windows, with precompiled kernels and no HSA_OVERRIDE workaround.

Official support still does not mean parity with CUDA. The fastest measured llama.cpp result on this card was on Vulkan, not ROCm (127 tok/s, or 156 with AMDVLK and a patch). Ollama ships ROCm 6.x libraries that have no gfx1201 kernels, so its GPU discovery times out and it falls back to the CPU until you set OLLAMA_VULKAN=1. You still have to choose a backend for each model, rather than install one thing that works.

Prefill rules it out for long-context work. The R9700 processes a 512-token prompt at 2,713 tok/s versus the 5090's 7,026, and the gap widens to 3.44× at 32K. Agents, retrieval over documents and long chats all send a long context with every request, so for them prefill is the speed that you notice most, and it is where this card is weakest. It is a good low-cost card for short prompts and batch jobs, and a poor one for long-context work.

Context, which changes all of the above

Every number in the matrix is measured at depth zero, and you will almost never run at depth zero. A chat re-sends the whole conversation with each message, and agents and document retrieval add long tool outputs and documents on top, so context adds three separate costs. You need memory to hold the KV cache, you wait for prefill before the first token, and decoding slows down, because attention reads the entire cache for every new token.

The non-obvious part

MoE models slow down more with context than dense models do. The KV cache adds to the memory read for each token, and an MoE model reads very little else, because only its active parameters are read.

gpt-oss-120b reads about 2.7 GB of active weights per token. Only half of its layers use full attention (the other half keep a 128-token window), so its KV cache at 32K context is about 1.2 GB. At that depth the model reads about 45% more memory per token than at depth zero, which fits the 33% decode slowdown measured on the Spark. A dense 70B model reads about 36 GB of weights per token. Its cache at 32K is about 10 GB, which adds more than a quarter, so it slows down by about a fifth. The Spark is strongest on MoE models, and context erodes that strength fastest.

Two Sparks or one Mac

Two Sparks cost ~$15,400 and give you about 220 GB of usable memory at 273 GB/s. A 256 GB M5 Ultra costs ~$12,000 and gives you about 230 GB at 1,200 GB/s. The Mac is $3,400 cheaper, with slightly more memory and 4.4× the bandwidth.

The 512 GB Mac, at ~$24,750, is in a different budget. At the Spark pair's price, the fair comparison is the 256 GB machine, and the pair loses to it on every hardware measure in the tables above.

CUDA is the one real argument for the Spark. The Mac has no upstream vLLM, no NVIDIA container stack, and a much smaller fine-tuning ecosystem. If you need to develop against the same stack that you deploy to, a single Spark is still worth buying. A second one is not.

The Spark cluster: no measurement

Nobody has published an equivalent measurement for a two-Spark cluster, so it does not belong in the table above.

Here is what is known. The two Sparks are joined by a 200GbE ConnectX-7 link. Under pipeline parallelism each layer still runs once, so the second box adds capacity but not throughput. The flat two-Spark figure on this page comes from that reasoning, and it is an inference from the interconnect, not a benchmark. NVIDIA has published nothing comparable to Apple's four-node numbers. EXO gains speed on Macs by spreading the expert weights so that each node reads less memory per token. A Spark cluster might gain in the same way if it ran a similar expert-parallel setup over RDMA. Treat the two-Spark throughput figure as a conservative, untested assumption. If that configuration is on your shortlist, look for a benchmark first.

What the measurements show

The runtime determines whether clustering helps at all. Compare rows one and three. With the same model, hardware and interconnect, EXO with RDMA gains 34% on two nodes, while llama.cpp loses 16%. If you add a second Mac and run the wrong software, the pair is slower than one machine. You cannot buy this as a hardware feature. You have to configure it.

Very large MoE models run slower than the bandwidth formula predicts. The figures above are from M3 Ultra machines at 819 GB/s. Scaled by bandwidth, they put a single M5 Ultra at about 31 tok/s on DeepSeek 671B and 29 on Qwen3 235B. The formula alone would predict about 48 and 50–80. These models reach well below the efficiency of mid-size models, most likely because expert routing scatters the memory reads. The matrix uses the measured figures.

Two 256 GB Macs cost less than one 512 GB Mac. The pair comes to ~$24,000 delivered and the single machine to ~$24,750. The pair is $750 cheaper, with 20 GB less memory and about 34% more throughput. The single machine is simpler: one box instead of two, and no dependence on EXO or the RDMA link.

Three conclusions about the stacks

The Spark's CUDA advantage is narrower than "it runs CUDA" suggests. It runs aarch64 CUDA on compute capability sm_121. NGC containers work, but many pip wheels do not. You will hit bugs that are specific to this compute capability, such as the fallback from FP4 to Marlin kernels, before most other users do, because few people own one. It is not a drop-in Linux CUDA box, and working around these problems takes real time.

The Mac is a very good inference machine and a poor development platform. MLX runs 20–40% faster than llama.cpp on the same chip, so the M5 Ultra estimates here may be low. Upstream vLLM does not run on Metal, but the community vllm-mlx project reimplements the important parts: continuous batching, a paged KV cache and prefix caching. What the Mac lacks is the fine-tuning toolchain. PEFT, TRL, Unsloth and Axolotl are CUDA projects, and MLX's own LoRA tools are a separate ecosystem. If the job is serving models, the Mac is fine. If it includes conventional fine-tuning or running research code as published, it is not.

On AMD's integrated chips, the software cancels out the memory. On Strix-class hardware (gfx1151), the Vulkan backend beats AMD's own ROCm on llama.cpp prompt processing by about 2.5× (880 versus 350 tok/s on Llama-2-7B Q4_0). The HIP path is barely faster than the CPU for prefill, and the gfx1151 rocBLAS kernels are several times less efficient than the discrete-GPU versions. PyTorch needs community wheels, because there are no official ones. Gorgon Halo offers 160 GB for $3,999, the most memory per dollar of anything mentioned here, and it is still hard to recommend.

What this means for timing

The usual reason to wait is that something better is close. Nothing is.

Apple's next Studio is expected in 2028. NVIDIA has announced no Spark successor and is putting the GB10 chip into laptops. AMD's Gorgon Halo adds memory to 2025 silicon, and its real successor arrives in 2027 at the earliest. DRAM prices are rising, so waiting is likely to cost money rather than save it. The one interesting item on the horizon is LPDDR6. If Medusa Halo ships at 691 GB/s with a large memory pool, it breaks the trade between capacity and bandwidth that this whole page is about. But it is two years away and unconfirmed, so you cannot plan a purchase around it.

Where the $1,300 goes

The upgrade buys 25% more GPU cores and 20% more CPU cores. It buys no extra memory bandwidth, and bandwidth is the only thing that decode speed depends on.

Decode speed is the same in both bins. The 36/80 bin prefills about 25% faster, which saves about 3 seconds on a 32K-token prompt. That matters if most of your work uses long prompts, and hardly at all if your prompts are short. For short-prompt work the 64-core bin would be the better buy. But Apple's configurator appears to offer 256 GB only with the 36/80 bin. If so, there is no choice to make, and the delivered price is ~$12,000 rather than the $9,499 that the base bin would cost before tax. Every price on this page is for the 36/80 bin. Check the configurator before you budget against the lower figure.

The same logic applies to storage. Apple charges $500 to go from 1 TB to 2 TB, which is $500/TB. A Thunderbolt 5 NVMe enclosure costs about $250, and Gen 4 drives cost about $100–130/TB during the NAND shortage. A 4 TB external drive therefore comes to about $175/TB. It reads at about 6,000 MB/s, roughly 80% of the speed of the Mac's internal SSD, so a 60 GB model loads in about ten seconds. Take the 1 TB internal drive and put the savings toward more memory.

Which one, and when

Start with the largest model that you need to run, because its size sets the minimum memory. Above that floor, more bandwidth means faster generation, and more compute means faster prefill on long prompts. Then check that the software stack runs what you need. Each recommendation below names the priority that it serves.

If value rules · ~$3,660

Dual RTX 3090

The only NVIDIA option under $5,000. Memory costs $76/GB versus the 5090's $188, and it runs a 70B dense model entirely on the GPUs, which the 5090 cannot. You pay for that with 700 W and a build that you have to design yourself.

If VRAM per dollar rules · ~$2,550

Radeon AI PRO R9700

32 GB for 42% of a 5090's price, at $80/GB versus $188. ROCm 7.2 supports it officially, unlike AMD's integrated chips. But prefill runs 3.44× slower than on a 5090 at 32K context, so it suits short prompts and batch jobs, not long-context work.

If latency rules · ~$6,000

Single RTX 5090

The lowest latency per dollar on models that fit in 32 GB. But it is the worst memory value here apart from the PRO 6000, and supply is thin enough that used cards sell above new ones. Buy it only if 32 GB really covers what you run.

If CUDA parity rules · ~$7,700

DGX Spark 128GB

The only machine here with the same architecture as a GB200 deployment target, and the cheapest CUDA machine that holds a 120B MoE model. At $70/GB it is not a memory-value buy. Buy it to match your deployment stack, not for the memory.

Avoid · ~$5,550

DGX Spark 64GB

Worse memory value than the 128 GB model ($101/GB versus $70), and its ~55 GB of usable memory will not hold gpt-oss-120b. It is a cheaper Spark that cannot do the job that people buy Sparks for.

Best all-round · ~$12,000

M5 Ultra 256GB

230 GB at 1,200 GB/s. It costs $3,400 less than two Sparks, with slightly more memory and 4.4× the bandwidth, and it ties for the best memory value on the page. You give up CUDA and the fine-tuning toolchain.

If one box matters · ~$24,750

M5 Ultra 512GB

480 GB in a single machine, running DeepSeek V3.2 at Q4 at about 31 tok/s. At $52/GB its memory is no cheaper than the 256 GB model's, and two of those cost $750 less with more throughput. Buy this because one machine is simpler to run, not to save money.

If frontier weights rule · ~$49,500

2× M5 Ultra 512GB

~960 GB, enough for Kimi K2.5 at a trillion parameters or DeepSeek V3.2 at Q8. It is the only option here that runs frontier open weights at full quality. At $49,500 this is a capital decision, not a hardware purchase. Requires EXO and macOS Tahoe 26.2.

Better than the 512 · ~$24,000

2× M5 Ultra 256GB

~460 GB, with about 34% more throughput than a single machine, for $750 less than one 512 GB machine. You give up 20 GB and take on the work of running a cluster. Unless you need everything in one box, this is the better way to spend $24,000.

Avoid · ~$15,400

2× DGX Spark 128GB

It costs $3,400 more than a 256 GB M5 Ultra, for about the same memory and less than a quarter of the bandwidth. At $56.41 per GB/s it is the worst bandwidth value on the page. Buy it only if you need more than 200 GB of memory on CUDA.

Method and confidence

Prices are delivered cost: street price plus about 11% sales tax (a US West Coast metro rate), applied to every configuration so that they compare fairly. Substitute your own rate. The GPU configurations also include a host PC, at about $500 before tax for a single-card build, $600 for a dual-card build and $1,500 for the RTX PRO 6000 workstation. Street prices were checked between 19 October and 1 November 2026. They are asking prices, not completed sales.

Pre-tax street prices. RTX 3090 used $1,350, new $1,550–$1,950. RTX 5090 new from $4,921 and used from $5,880, versus a $1,999 MSRP. Tom's Hardware has reported, without confirmation, that NVIDIA has stopped GB202 production for consumer cards. DGX Spark 128GB $6,950 and 64GB $4,999. RTX PRO 6000 $15,999–$16,000. Radeon AI PRO R9700 $1,800 a card, versus a $1,299 MSRP that no retailer charges. The lowest tracked US price was $1,827 on 26 October, and Amazon listings were near $1,700 in mid-October. The 12-month median is $1,460, and used listings start at about $1,907.

Mac Studio with M5 Ultra. It starts at $5,499 for the 30-core CPU / 64-core GPU bin with 96 GB and 1 TB. Upgrades cost $1,300 for the 36/80 bin, $4,000 for 256 GB and $500 for 2 TB. The configurator appears to offer 256 GB only with the 36/80 bin, so the working figure is $10,799 before tax, about $12,000 delivered, as confirmed in a real configurator session. The 512 GB model costs $22,299 with the 36/80 bin and 1 TB, about $24,750 delivered. Its memory option alone is $15,500. The first 160 GB above the 96 GB base cost $25/GB, and the next 256 GB cost $45/GB, so do not extrapolate Apple's memory prices in a straight line.

Prices are moving fast. Between late August and October 2026, NVIDIA raised the DGX Spark 128GB from $4,699 to $6,950, an increase of 48%. Used RTX 3090s rose 23% from $1,095–$1,181. The lowest new RTX 5090 price rose about 13% from $4,288–$4,381, and the RTX PRO 6000 rose from $13,998–$15,499. Apple has not changed its prices since the M5 Ultra launched on 25 August. Check current prices before you buy.

Performance. R9700 figures are measured llama.cpp results on a single card. It runs Qwen3.5-35B-A3B at 127.4 tok/s on Vulkan, or 156.3 when tuned, and Qwen3.5-27B dense at 29–33 tok/s. With a tuned ROCm build it runs Qwen2.5-Coder-7B at ~99 tok/s, and it prefills a 512-token prompt at ~2,713 tok/s. The dual-card figures are based on layer splitting, so decode speed matches a single card and only capacity grows. The dual-card 70B figure is derived, not measured. The DGX Spark gpt-oss results are measured, and come from the llama.cpp benchmark thread. The RTX 3090 and RTX PRO 6000 results are measured, and come from published llama.cpp and Ollama runs. The M5 Max results at 614 GB/s come from hardware-corner's benchmark set, including gpt-oss-120b Q8 at 87.9 tok/s decode and 1,325 tok/s prefill. All M5 Ultra figures are derived, not measured. They are scaled from the M5 Max results by the 1.95× bandwidth ratio, since the Ultra is two Max dies. Apple claims 4.3× the AI compute of the M3 Ultra, so prefill may beat these estimates. RTX 5090 speeds come from RTX PRO 6000 measurements, since both use the GB202 die at the full 1,792 GB/s. Other derived figures use tok/s ≈ bandwidth × efficiency ÷ bytes read per token. Treat every figure as ±20%.

Context figures. KV cache sizes are calculated from published model architectures (2 × layers × KV heads × head dim × bytes), not measured. They come to about 0.32 MB per token for a Llama-class 70B and 0.26 MB for a 32B. gpt-oss-120b needs only about 0.036 MB per token, because it uses grouped-query attention and half of its layers keep only a 128-token window. Time to first token is the context length divided by the prefill rate at that depth. The Spark's depth curve is measured: decode falls from 60.57 tok/s at depth 0 to 40.55 at 32K, and prefill falls from 1,956 tok/s to 1,027. The other columns apply the same shape, because the slowdown depends on the ratio of KV cache to weights rather than on the machine.

Structural caveats. Dual-3090 speeds are based on llama.cpp layer splitting, where the cards work in turn and effective bandwidth stays at 936 GB/s. vLLM tensor parallelism reaches about 1.4–1.6× that, with a more fragile setup. Two-Spark figures are based on pipeline parallelism over the 200GbE ConnectX-7 link, which adds capacity but not throughput. NVIDIA has not published cluster-scaling figures comparable to Apple's, so that flat figure is an inference from the interconnect. An expert-parallel Spark cluster with RDMA might do better. Multi-Mac figures come from four M3 Ultra Studios at 819 GB/s, scaled by bandwidth to the M5 Ultra. They require macOS Tahoe 26.2 for the Thunderbolt 5 RDMA driver and EXO as the runtime. They do not apply to llama.cpp, which gets slower as you add nodes. Batching and prefix caching on Apple silicon require the community vllm-mlx server, not mlx-lm or llama.cpp.
