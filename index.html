Local inference hardware / Prices rechecked 1 Nov 2026 / Windows 11 + WSL2 workstation

Every rig is short of bandwidth or short of room.

Token generation is memory-bandwidth-bound, and model size sets the floor on memory. Those two numbers decide almost everything else, and nothing here is generous with both at a sane price, so what you are really buying is memory. Seven weeks after the August pass, the conclusions have moved: NVIDIA raised the DGX Spark 48% and the RTX 5090 trades 60% higher, while Apple has not changed a price. The machine that looked expensive in August is now the value option.

A correction, and then the catch

AMD's software story is better than this page said. The earlier verdict here came from Strix Halo (gfx1151), where Vulkan beat AMD's own ROCm by 2.5× and PyTorch needed community wheels. The discrete R9700 is gfx1201, and ROCm 7.2 lists it as officially supported on Linux and Windows with precompiled kernels and no HSA_OVERRIDE workaround. That is a real improvement and the earlier blanket dismissal of AMD does not transfer to this card.

Official support is still not the same as parity. The fastest measured llama.cpp result on this card was on Vulkan, not ROCm (127 tok/s, rising to 156 with AMDVLK plus a patch), and Ollama ships ROCm 6.x libraries with no gfx1201 kernels, so discovery times out and falls back to CPU until you set OLLAMA_VULKAN=1. You are still choosing your backend per model rather than installing one thing that works.

And prefill is the disqualifier for agentic work. 2,713 tok/s against the 5090's 7,026 at a 512-token prompt, widening to 3.44× slower at 32K. An agent loop re-sends its whole context every turn, so prefill is the number you feel most and the one where this card is weakest. It is an excellent cheap-VRAM card for batch work and a poor one for the job on this page.

Context, which changes all of the above

Every number in the matrix is a depth-zero number, and you will almost never run at depth zero. An agentic loop re-sends its whole conversation each turn, so context imposes three separate costs: memory to hold the KV cache, seconds of prefill before the first token, and a permanent decode slowdown because attention reads the entire cache on every token generated.

The non-obvious part

MoE models decay faster with context than dense ones, because the KV cache is compared against active parameters rather than total.

gpt-oss-120b reads about 2.7 GB of active weights per token. Its KV cache at 32K context is roughly 2.4 GB. So at that depth the model is reading nearly twice as much memory per token as it was at depth zero, which is exactly the 33% slowdown the Spark benchmarks show. A dense 70B model reads 40 GB of weights against the same few GB of cache and barely notices. The Spark's whole advantage lives in MoE models, and that advantage is the thing context erodes fastest.

Seven weeks changed the answer

In August, two Sparks (~$11,000) and one 256GB M5 Ultra (~$12,000) held the same memory for roughly the same money, and the Mac's 4.4× bandwidth made it the better buy by a nose. Today two Sparks cost ~$15,400 and the Mac still costs ~$12,000. The Mac is now $3,400 cheaper with the same memory and four times the bandwidth.

The cleaner comparison at that budget is now a 256 GB Mac, not a 512 GB one. Apple priced the 512 GB tier at $22,299 on 28 October, well above the ~$16,000 this page had extrapolated, so two Sparks at ~$15,400 are no longer within reach of it. Against the 256 GB machine at ~$12,000 they lose outright on every axis; against the 512 GB machine at ~$24,750 they are simply a different budget.

CUDA remains the one real defence: the Mac has no upstream vLLM, no NVIDIA container stack, and a much thinner fine-tuning ecosystem. If the purchase exists to develop against the stack you deploy to, a single Spark still earns its place. Two of them no longer do at any price on this page.

The Spark side, stated honestly

There is no equivalent measurement for a two-Spark cluster, so it does not belong in the table above.

What is known: the two Sparks are joined by a 200GbE ConnectX-7 link, and under pipeline parallelism each layer still executes once, which yields capacity without throughput. That is the basis for the flat figure used elsewhere on this page, and it is inference from the interconnect, not a benchmark. NVIDIA has published nothing comparable to Apple's four-node numbers. Given that EXO gains on Macs specifically by distributing expert weights so each node reads less memory per token, a Spark cluster running a comparable expert-parallel setup over RDMA could plausibly do the same. Treat the two-Spark throughput number as a conservative assumption that has not been tested, and if that configuration is on your shortlist, go looking for a benchmark before believing this page.

Two findings, one of which corrects this page

The runtime decides whether clustering helps at all. Compare rows one and three: same model, same hardware, same interconnect, and EXO with RDMA gains 34% on two nodes while llama.cpp loses 16%. Adding a second Mac and running the wrong software makes your setup slower than a single machine. This is not a hardware property you can buy; it is a configuration you have to get right.

These measurements say my single-node Mac estimates were optimistic. The figures above are M3 Ultra at 819 GB/s. Scaling by bandwidth puts a single M5 Ultra at roughly 31 tok/s on DeepSeek 671B and 29 on Qwen3 235B, not the 48 and 50–80 this page previously derived from bandwidth arithmetic alone. Very large MoE models evidently run at well under the efficiency that mid-size models achieve, most likely because expert routing scatters memory access. The matrix now uses the measurement-derived figures.

And the pair now wins, which is a reversal. This page previously said two 256 GB machines cost $6,400 more than one 512 GB machine for less memory. That rested on an estimated 512 GB price of ~$17,600. Apple published the real number on 28 October: $22,299, or ~$24,750 delivered. Two 256 GB machines come to ~$24,000. So the pair is now $750 cheaper, with 20 GB less memory and about 34% more throughput. The single box still wins on simplicity, one machine rather than two, and no dependency on EXO or the RDMA path. But it is no longer the cheaper option, and the earlier conclusion was an artifact of my estimate rather than of Apple's pricing.

Three conclusions that change the ranking

The Spark's CUDA advantage is narrower than "it runs CUDA" implies. It is aarch64 CUDA on compute capability sm_121, which means NGC containers work but many pip wheels do not, you meet compute-capability-specific bugs like the FP4-to-Marlin fallback before anyone else does, and the user population finding those bugs is small. It is not a drop-in Linux CUDA box, and the weekends it costs are real.

The Mac is an inference appliance, not a development platform, and it is very good at being one. MLX runs 20–40% faster than llama.cpp on the same silicon, which means the M5 Ultra estimates here may be conservative rather than optimistic. Upstream vLLM does not run on Metal, but the community vllm-mlx project reimplements the important parts: continuous batching, a paged KV cache, prefix caching, and an Anthropic /v1/messages endpoint that Claude Code can be pointed at directly. What genuinely does not exist is the fine-tuning toolchain: PEFT, TRL, Unsloth and Axolotl are CUDA projects, and MLX's own LoRA is a separate ecosystem. If the job is serving models, the Mac is fine. If it includes fine-tuning conventionally or running arbitrary research code, it is not.

AMD's memory advantage does not survive contact with its software. On Strix-class hardware the Vulkan backend beats AMD's own ROCm on llama.cpp prompt processing by roughly 2.5× (880 versus 350 tok/s on Llama-2-7B Q4_0), the HIP path barely beats CPU for prefill, gfx1151 rocBLAS kernels run several times less efficiently than their discrete-GPU equivalents, and PyTorch needs community wheels because official ones do not exist. Gorgon Halo's 160 GB at $3,999 is the best capacity-per-dollar on this page and I still would not buy it.

What this means for timing

The usual reason to wait is that something better is close. Right now nothing is.

Apple's next Studio is 2028. NVIDIA has announced no Spark successor and has moved GB10 into laptops. AMD's Gorgon Halo is a memory bump on 2025 silicon, and its real successor is 2027 at the earliest. Meanwhile DRAM prices are rising, not falling, so waiting costs money rather than saving it. The one genuinely interesting item on the horizon is LPDDR6: if Medusa Halo lands at 691 GB/s with a large memory pool, it breaks the capacity-versus-bandwidth trade this whole page is built on. That is two years away and unconfirmed, which is not a plan you can buy against today.

Where the $1,300 goes

The upgrade buys 25% more GPU cores and 20% more CPU cores. It buys zero extra memory bandwidth, which is the only thing decode speed depends on.

In an agentic turn you prefill once and decode thousands of times, so decode dominates wall-clock and decode is identical across the bins. For inference alone the 64-core bin would be the better buy. But the configurator appears to pair 256 GB only with the 36/80 bin, in which case the choice does not exist and the delivered price is ~$12,000 rather than the $9,499 a base-bin machine would cost. Every price on this page assumes the 36/80 bin. Verify in the configurator before budgeting against the lower figure.

Same logic on storage: Apple charges $500 to go from 1 TB to 2 TB, which is $500/TB. A Thunderbolt 5 NVMe enclosure is about $250 once, plus Gen 4 drives at roughly $100–130/TB in the current NAND shortage, so a 4 TB external lands near $175/TB all-in and streams weights at about 6,000 MB/s. That is roughly 80% of the Mac's internal SSD, and it turns a 60 GB model load into a ten-second wait. Take the 1 TB internal and put the difference toward the memory tier.

Dual RTX 3090

32 GB for 42% of a 5090's price, at $80/GB against $188. ROCm 7.2 supports it officially now, which is more than AMD's integrated parts can say. But prefill runs 3.44× slower than a 5090 at 32K context, so it is the wrong card for an agent loop and a good one for batch work.

If latency rules · ~$6,000

Single RTX 5090

Still the lowest latency per dollar on models that fit in 32 GB. But it is now the worst memory value here outside the PRO 6000, supply is reportedly thin enough that used trades above new, and it costs more than a 128 GB Spark. Buy only if 32 GB genuinely covers you.

If CUDA parity rules · ~$7,700

DGX Spark 128GB

Still the only machine here that is the same architecture as a GB200 target, and still the cheapest CUDA path to a 120B MoE. But $4,699 became $6,950, so the value case that justified it is gone. Buy it for stack parity now, not for the memory.

Avoid · ~$5,550

DGX Spark 64GB

Costs more than the 128 GB model did in August, has worse memory value than the 128 GB does now ($101/GB against $70), and ~55 GB usable will not hold gpt-oss-120b. It is a cheaper Spark that cannot do the thing Sparks are for.

Best all-round · ~$12,000

M5 Ultra 256GB

230 GB at 1,200 GB/s, unchanged in price while everything NVIDIA sells rose. Now $3,400 cheaper than two Sparks with the same memory and four times the bandwidth, and the best memory value on the page outside the unpriced 512. Costs you CUDA and fine-tuning.

If one box matters · ~$24,750

M5 Ultra 512GB

480 GB in a single machine, running DeepSeek V3.2 at Q4 around 31 tok/s. At $52/GB it offers no better memory value than the 256 GB model, and two of those cost $750 less with more throughput. Buy this for operational simplicity, not economics.

If frontier weights rule · ~$49,500

2× M5 Ultra 512GB

~960 GB, enough for Kimi K2.5 at a trillion parameters or DeepSeek V3.2 at Q8, and still the only entry here that runs frontier open weights at frontier quality. At a confirmed $49,500 this is now a capital decision, not a hardware purchase. Requires EXO and macOS Tahoe 26.2.

Better than the 512 · ~$24,000

2× M5 Ultra 256GB

~460 GB at roughly 34% more throughput than a single box, and now $750 cheaper than one 512 GB machine once Apple's real 512 price landed. You give up 20 GB and take on cluster ops. For anything but a hard single-box requirement, this is the better $24k.

Avoid · ~$15,400

2× DGX Spark 128GB

October's 48% increase finished this one off. It now costs $3,400 more than a 256 GB M5 Ultra with the same memory and a quarter of the bandwidth, and the worst bandwidth-per-dollar on the page at $56.41. Only a hard 200 GB-of-CUDA requirement justifies it.

Method and confidence

Prices are delivered cost, meaning street price plus about 11% sales tax (a US West Coast metro rate), applied uniformly so the comparison holds; substitute your own rate. Underlying pre-tax street rates as of 19 October 2026, with the August figures shown for contrast. RTX 3090 used $1,350 (was $1,095–$1,181, +23%), new $1,550–$1,950; RTX 5090 new floor $4,921 and used floor $5,880 against a $1,999 MSRP (was $4,288–$4,381, +64% new and +60% used, with used now above new on thin stock, and an unconfirmed Tom's Hardware report that NVIDIA has halted GB202 production for consumer cards); DGX Spark 128GB $6,950, raised 3 October from $4,699 and from $3,999 at launch, with a new 64GB SKU at $4,999 shipping from partners 23 October; RTX PRO 6000 $15,999–$16,000 retail (was $13,998–$15,499). Radeon AI PRO R9700 carries a $1,299 MSRP that nobody pays: the working figure here is $1,800 a card, from a lowest tracked US price of $1,827 on 26 October, Amazon listings near $1,700 in mid-October, a 12-month median of $1,460, and used listings starting about $1,907. Asking prices, not completed sales. M5 Ultra Mac Studio starts at $5,499 for the 30-core CPU / 64-core GPU bin with 96 GB and 1 TB. The ladder from there: +$1,300 for the 36/80 bin, +$4,000 for 256 GB, +$500 for 2 TB. The configurator appears to pair 256 GB only with the 36/80 bin, so the working figure is $10,799 pre-tax, about $12,000 delivered, confirmed against a real configurator session. Apple has not changed its existing prices since 25 August, which is why every Apple row reads "unchanged" and why the relative conclusions moved without Apple doing anything. The 512 GB tier went on sale 28 October at $22,299 for the 36/80 bin with 1 TB, about $24,750 delivered. The memory option alone is $15,500. Note what that implies: the first 160 GB above the 96 GB base costs $25/GB, and the next 256 GB costs $45/GB. This page previously estimated $16,000 by extrapolating Apple's 96→256 rate linearly, and was low by $6,300. Apple's memory ladder escalates at the top tier; do not extrapolate it straight.

Performance. R9700 figures are measured llama.cpp results on a single card: 127.4 tok/s on Vulkan for Qwen3.5-35B-A3B rising to 156.3 tuned, 29–33 tok/s on Qwen3.5-27B dense, ~99 tok/s on Qwen2.5-Coder-7B with a tuned ROCm build, and ~2,713 tok/s prefill at 512 tokens. Its dual-card figures assume layer splitting, so decode matches a single card and only capacity grows; the 70B estimate there is derived, not measured. Measured: DGX Spark gpt-oss figures from the llama.cpp benchmark thread; RTX 3090 and RTX PRO 6000 figures from published llama.cpp and Ollama runs; M5 Max figures at 614 GB/s from hardware-corner's benchmark set, including gpt-oss-120b Q8 at 87.9 tok/s decode and 1,325 tok/s prefill. All M5 Ultra numbers here are derived, not measured — scaled from those M5 Max results by the 1.95× bandwidth ratio, since the Ultra is two Max dies. Apple's claimed 4.3× AI compute over M3 Ultra suggests prefill could beat this estimate. RTX 5090 speeds come from RTX PRO 6000 measurements, since both use the GB202 die at the full 1,792 GB/s. Other derived figures use tok/s ≈ bandwidth × efficiency ÷ bytes read per token. Treat everything as ±20%.

Context figures. KV cache sizes are computed from published model architectures (2 × layers × KV heads × head dim × bytes), not measured: about 0.32 MB per token for Llama-class 70B, 0.26 MB for a 32B, and 0.072 MB for gpt-oss-120b, whose grouped-query attention and sliding-window layers make it unusually cheap. Time-to-first-token is context ÷ prefill rate at that depth. The Spark's depth curve is measured (60.57 tok/s decode at depth 0 falling to 40.55 at 32K; 1,956 tok/s prefill falling to 1,027); the other columns apply the same shape, since the decay is a property of the KV-to-weights ratio rather than of the machine.

Structural caveats. Dual-3090 speeds assume llama.cpp layer splitting, where cards work sequentially and effective bandwidth stays at 936 GB/s; vLLM tensor parallelism reaches roughly 1.4–1.6× that with a more fragile setup. Two-Spark figures assume pipeline parallelism over the 200GbE ConnectX-7 link, which adds capacity but not throughput; NVIDIA has not published cluster-scaling figures comparable to Apple's, so that flat number is inference from the interconnect rather than a measurement, and a tensor-parallel Spark cluster with RDMA might do better than shown. Multi-Mac numbers come from four M3 Ultra Studios at 819 GB/s, scaled by bandwidth to the M5 Ultra; they require macOS Tahoe 26.2 for the Thunderbolt 5 RDMA driver and EXO as the runtime, and do not apply to llama.cpp, which scales negatively across nodes. Apple-silicon batching and prefix caching assume the community vllm-mlx server rather than mlx-lm or llama.cpp.
